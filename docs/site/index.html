ahsir — A Multi-Agent Scheduler over A2A

A small Go control plane that runs LLM-backed agents as local processes, lets them talk over the A2A protocol, and lets Claude Code or Codex drive the fleet through a CLI and a bundled skill — local-first, recoverable, and auditable.

Official documentation · generated 2026-06-08

1 · Overview

What ahsir is

ahsir turns the Claude and Codex CLIs into A2A-compatible runtimes and schedules a fleet of them on one machine. Each agent is a persistent persona — a fixed system prompt, a provider backend, its own filesystem permissions, and durable per-conversation memory — addressable over the A2A protocol. A central scheduler owns agent lifecycle, a discovery registry, and an HTTP gateway that mediates every call so traffic is visible, recoverable, and auditable.

You drive it two ways, both backed by the same CLI:

  • Directly — ahsir list / chat / status / trace / history / doctor.
  • Through an agentic host — Claude Code or Codex load the bundled orchestrator skill, which teaches the host when to delegate to a specialist agent and how to call the CLI.

What it is not

  • Not an MCP replacement. The control surface is the CLI plus a skill. An MCP server mode was considered and deliberately deferred (see Roadmap).
  • Not a cloud agent platform. The differentiator is being local-first, CLI-native, recoverable, and auditable — not a hosted multi-tenant service.
  • Not (yet) a multi-machine system. The scheduler binds loopback; the trust boundary is a single OS user on one host.

Mental model

Think of ahsir as a process supervisor + message router for personas. A persona (agent) is configured once in an agent-card.yaml; the scheduler spawns it, keeps it alive, registers it for discovery, and routes A2A messages to it. Conversations are keyed by an A2A contextId; the agent holds memory for that context inside a long-running provider subprocess, and the scheduler can resume it after a crash.

2 · Design principles

Every feature below is an expression of these five commitments. When two goals conflict, this is the priority order used to decide.

1 · Local-first, zero-config by default. The common path — one OS user on one machine — must work with no setup. Secrets auto-generate, the CLI auto-discovers them, ports auto-allocate. Friction is only introduced where a real threat justifies it.
2 · CLI-native, not protocol-first. The control surface is text-in/text-out commands an agent (or a human, or a shell pipe) can drive. Structured protocols (A2A on the wire, a future MCP mode) serve the CLI, not the reverse.
3 · Recoverable. A crashed agent, a killed claude, a restarted scheduler — none should lose a conversation. State that matters (context→session mappings, the invocation ledger, transcripts) is persisted so work resumes instead of restarting.
4 · Auditable. Every mediated call is recorded. ahsir trace reconstructs the agent-call graph; ahsir history replays a conversation. The scheduler sits in the path precisely so nothing is invisible.
5 · Honest boundaries. Where a guarantee isn't real yet, it is named as deferred rather than implied. Hardening precedes expansion: the system is explicit about what is a foundation versus what is potential.

Request flow

Two entry points converge on the same agent-side path. The scheduler stays in the loop for discovery, mediation, and auditing.

  Claude Code / Codex ──(orchestrator skill)──┐
                                              ▼
  human / shell ──────────► ahsir CLI ──► scheduler gateway  :9800
                                              │   POST /agents/{name}/chat        (buffered)
                                              │   POST /a2a/{name}                (native A2A proxy)
                                              │   GET  /agents/{name}/tasks/{id}  (task status)
                                              │   GET  /agents/{name}/history/{ctx}
                                              │   GET  /agents, /invocations, /config/timeouts
                                              │   POST/DELETE /admin/agents       (gated)
                                              ▼
                              registry (discovery)  +  invocation ledger (audit)
                                              │
                            A2A JSON-RPC message/send | message/stream
                                              ▼
                    ahsir-agent  :loopback        ahsir-agent  :loopback
                    ├ A2A server (token-gated)    ├ A2A server
                    ├ executor (agent loop)       ├ executor
                    └ SessionPool by contextId    └ SessionPool by contextId
                              │                              │
                    claude --resume / codex exec resume <thread>

A turn proceeds: gateway records an invocation in the ledger → forwards to the agent over A2A → the executor opens (or resumes) the Session for that contextId → the provider produces the reply → the executor records a transcript turn → the gateway settles the ledger entry and returns.

Process & trust model

  • The scheduler binds 127.0.0.1 only. A non-loopback network.bind is explicitly rejected.
  • Agents run as child processes of the scheduler, each on an auto-allocated loopback port.
  • Scheduler→agent A2A calls carry a per-agent internal token the wrapper verifies; the scheduler only sends it to the loopback address it recorded at spawn time.
  • The control plane (agent lifecycle, registry write) is gated by an admin token. The trust boundary is the OS user who can read that token's 0600 file.

4 · Core concepts

TermMeaning
Agent / persona A configured specialist: fixed system prompt, provider, filesystem permissions, skills. One ahsir-agent process, defined by an agent-card.yaml.
contextId The A2A conversation key. All messages sharing a contextId hit the same provider session and accumulate memory. Omit it for one-shot isolated turns.
Session A provider-backed conversation runtime. ClaudeSession is one long-running claude subprocess; CodexSession forks codex exec per turn and resumes by thread id. Both implement one Session interface.
SessionPool Maps contextId → Session, with idle eviction (sessionID retained for resume), a concurrency cap, and the per-context FIFO turn gate.
Registry Discovery: agents register a card and heartbeat; lookups resolve name→card. Liveness is derived on read.
Gateway The scheduler's single HTTP port. Mediates chat/task/history, proxies native A2A, exposes read views, and gates the control plane.

Transcript Per-context full conversation record (speaker, full text, full reply) the wrapper writes; backs ahsir history and the takeover workflow.

5 · Features

Scheduling & lifecycle

  • Scheduler-owned A2A entrypoint. Public native A2A traffic goes through POST /a2a/{agent}, so user calls and agent-to-agent calls are both visible to the scheduler and recorded.
  • Dynamic agent lifecycle — no scheduler restart. ahsir agent new scaffolds a card, registers it in ahsir.yaml, and starts it on the running scheduler via POST /admin/agents — the new agent hot-registers and is usable in list / chat right away; ahsir agent delete stops it (files preserved). A restart is only needed for --skip-start, a scheduler that was down, or a hand-edited ahsir.yaml. (Editing an existing card restarts that agent, not the scheduler.)
  • Supervision & restart. If an agent process exits unexpectedly, or its /healthz fails repeatedly, the scheduler restarts it on the same port with exponential backoff. Intentional stops are terminal (no restart).
  • Deterministic startup. Listeners bind synchronously so port conflicts surface as start errors; auto-allocated ports probe for bindability and skip foreign listeners; a failed Start unwinds everything already started.
  • Process-tree cleanup. Agents (and their provider subprocesses) run in process groups so shutdown reaps the whole tree.

Sessions & recovery

  • Multi-provider sessions. Anthropic (Claude), Zhipu and DeepSeek (Anthropic-compatible endpoints), and Codex. Provider, base URL, API key, and model are set per agent card; the wrapper translates them into the right env for the CLI.
  • Resumable conversations. Claude agents resume with claude --resume=<session_id>; Codex agents with codex exec resume <thread_id>.
  • Persistent session mapping. Each agent writes <workspace>/.a2a/sessions.json (contextId→sessionID), bounded by pool.evicted_ttl / pool.max_evicted, so a restart resumes prior conversations instead of starting fresh.
  • Per-turn timeout parity. Both providers enforce runtime.timeout as a real per-turn deadline; on expiry the turn fails cleanly and the session evicts with its sessionID preserved for resume.
  • Restart continuation. After a supervised restart, the scheduler uses the ledger to send a continuation prompt for interrupted work that has a contextId.
  • Pool capacity controls. pool.max_active caps concurrent live provider processes per agent; overload_policy is reject or evict-lru.
  • Conversation-record retention & deletion. There is no manual delete; records are pruned by time, automatically, at process startup (compaction). The invocation ledger (which drives the console's conversation list and trace) keeps completed records 7 days and incomplete ones 30 days (compacted on scheduler start). Each agent's transcript (the per-context message history) is deleted once its most recent turn is older than 30 days, along with its index.json entry (on agent start). Roundtable logs follow the same 30-day rule (on scheduler start). Separately, pool.evicted_ttl governs how long the session mapping is remembered, i.e. whether an old conversation can still --resume.

Shared-context collaboration 2026-06-08

Several clients can work inside one contextId on the same machine.

  • Speaker attribution. ahsir chat --as <name> (default: OS username) tags each turn; the executor prefixes the user text with [speaker: X] and adds a multi-speaker instruction to the system prompt so the model attributes statements to the right person. The speaker shows up in ahsir trace. Absent attribution, the prompt is byte-identical to before.
  • Per-context FIFO queue. A second turn arriving while one is in flight on the same context waits in arrival order instead of failing. Bounded by pool.queue_depth (default 4); a full queue degrades to the busy/409 signal, and queue_depth: 0 restores the prior fail-fast contract. Distinct contexts stay fully parallel.
  • Task-based async. ahsir chat --async submits the turn and returns a task id immediately (A2A configuration.blocking=false); poll it with ahsir status. The default mode submits then polls internally — same synchronous UX, no long-held connection.
  • Transcript replay. ahsir history <agent> <contextId> replays who said what and what the agent answered — the takeover path for someone joining a conversation mid-stream.
Privacy note. The transcript stores full conversation content (unlike the ledger's bounded preview) because replay is its purpose. It is written owner-only (0700 dir / 0600 files); the contextId is hashed into the filename so a caller-supplied id never reaches the filesystem raw. The sanctioned read path is the token-gated /history endpoint.

Rooms: multi-agent collaboration + roundtable 2026-06-11

A room hosts several agents in one shared conversation — they see each other's turns. The room id is the shared contextId, so it reuses the session + speaker machinery with no wrapper changes. A room has one of two floor-control modes (mode on POST /rooms, default relay):

① 多 Agent 协同 / multi-agent collaboration (mode: relay): hub-and-spoke, @-mention driven — for delegation-flavored collaboration.

  • @-mention turn-taking, usable by the operator and the agents. The first @<participant> in a message becomes the next speaker, so an agent can hand a question to a peer. Mentions inside code spans are quoted tokens, not directives.
  • Organizer fallback. A message addressing no one returns control to the room's organizer — operator (parks for your next message) or a designated moderator agent (it takes the floor and picks who continues).
  • Incremental relay. Each agent's turn is fed only the transcript it hasn't seen since it last spoke (a first-timer gets the full history). Bounded cost, no broadcast storm, no context loss — its own session retains everything up to its last turn and the delta fills the gap.
  • Runaway guard. An autonomous agent↔agent chain is bounded by maxChain turns between operator messages (default 8); each operator message resets it.

② 圆桌 / roundtable (mode: roundtable): the real round-table — consensus rounds (Texas Hold'em), flat, no chair — for a hard, ambiguous decision (e.g. an OKR review).

  • A round = one full pass over the participants in a fresh random order; each is asked in turn (a later speaker sees earlier same-round turns). Each contributes or, with no objection, replies 同意. The convention is injected per-turn — no agent system-prompt change needed.
  • Rolling consolidation. A dedicated moderator agent (not a participant, under its own <roomId>#mod contextId — no pollution of the shared transcript or participant sessions, and no say in who speaks) produces a visible 小结 each round that anchors the next round, in three columns: 【已达成】 (locked, carried forward, not relitigated unless an assumption breaks), 【待议】 (open, shrinking), and 【纠偏】 (steering — names @<agent> whose reasoning drifted off the proposition and tells them to reconverge). When 待议 empties, that's consensus and its 已达成 is the decision.
  • Budget (default 12 rounds) without consensus → parks for the operator; a new operator message re-opens a fresh cycle. Create with {"mode":"roundtable","participants":[...],"moderator":"<agent>","budget":12,"message":"<question>"}. Design: specs/2026-06-10-roundtable-mode.md.

HTTP: POST /rooms, GET /rooms, GET /rooms/{id}, POST /rooms/{id}/say, POST /rooms/{id}/stop. Roundtable turns are recorded in the ledger (source=roundtable) so they show in trace. Rooms are persisted (one <roomId>.jsonl per room) and reconstructed on scheduler restart; a recovered room returns in the waiting state (transient active/waiting status is not persisted, stopped is). Logs older than 30 days are compacted at startup. Runnable walkthrough: example/roundtable/.

Web console 2026-06-09

An optional, separate process (ahsir ui) that serves a single-page browser console and proxies the gateway. It holds no LLM and does no orchestration — a thin proxy + static SPA.

  • Chat 1:1 with any agent; replies render as Markdown (headings, bold/italic, code blocks, lists, blockquotes, links, GFM tables), each bubble showing the speaker and a timestamp.
  • Conversation list on the left, derived from the invocation ledger and keyed on contextId; a right rail with the agent's card details and the trace timeline.
  • Roundtable mode drives the /rooms API: create a room, watch the merged thread, send operator messages (with @), and stop.
  • Per-message actions (revealed on hover): 复制 copies the raw message text; 直接回复 (roundtable agent bubbles only) drops @<speaker> at the start of the composer. The right-rail participant rows and the agent-card header are also draggable onto the composer, inserting @<agent> at the caret.
  • Drop or paste a file onto the composer to attach its local path (paste a clipboard image with ⌘V too). Browsers hide a dragged/pasted file's real path, so the console uploads the bytes to POST /api/upload, copies them into a local upload dir, and inserts that absolute path at the caret (claude reads the file itself, e.g. 看下 /tmp/.../shot.png 报的什么错). Any file type, multiple at once.
  • Rooms + alerts. Both 多 Agent 协同 (relay) and 圆桌 (roundtable) create flows (see above); a roundtable thread is split by 「第 X 轮」 dividers with the moderator's consolidation as a 小结 card, and the trace is split per round too. @<participant> renders blue, @operator (you) as a deep-blue pill; a new agent @operator always shows an in-page toast, and when the tab is not active also fires a sound + browser popup + flashing tab that stops the moment you return to (or are already on) the page. Click a trace node to jump to its bubble; a jump-to-bottom button appears when scrolled up.

Upload dir defaults to $TMPDIR/ahsir-uploads (override with ahsir ui --upload-dir, or set AHSIR_UPLOAD_DIR to align the console and the agents in one place). An agent must run with filesystem.enabled: true to read a dropped file; such agents auto-allow-list the upload dir (--add-dir) at startup, so it works with zero per-agent config. Local-only by design. Markdown is XSS-safe (escape first, then tokenize to a fixed tag set; links limited to http(s)/mailto). Start it with ahsir ui --addr 127.0.0.1:9801 --scheduler http://127.0.0.1:9800.

MCP isolation 2026-06-09

Agents run their claude with --strict-mcp-config, so an agent never inherits the operator's global (~/.claude.json) or project (.mcp.json) MCP servers. The default — no mcp: block — means zero MCP servers: the isolated, fast, cheap baseline (inherited servers ballooned a trivial turn's input tokens and added per-call init, and are a privilege-bleed risk).

  • Opt in per agent via the card's mcp.servers (claude mcpServers shape, passed through verbatim) or ahsir agent new --mcp-config <file>.
  • Codex configures MCP through its own CODEX_HOME config.toml, so mcp.servers on a codex agent is an error rather than a silent no-op.

Model providers 2026-06-10

Each agent picks its model backend in the runtime block of its agent-card.yaml: claude (Anthropic plus Anthropic-compatible endpoints like DeepSeek/Zhipu) or codex. The high-level fields provider / baseURL / apiKey / model are translated into the env the CLI understands (see internal/wrapper/runtime.go).

Key rule: the wrapper only injects the vars you actually set. With baseURL and apiKey both empty, no ANTHROPIC_* env is exported and claude falls back to its own stored login. ${VAR} is expanded strictly (a missing var fails at agent startup); a non-empty baseURL with an empty apiKey is rejected (it would 401 silently).

A. Claude Code local login (no API key). Reuse the subscription/OAuth login already stored by claude (run claude, then /login).

runtime:
  command: claude
  provider: anthropic
  baseURL: ""        # empty → no ANTHROPIC_BASE_URL
  apiKey: ""         # empty → no token → claude uses its own login
  model: ""          # empty → Claude Code default; or e.g. claude-opus-4-8
  timeout: 600s

Requirements: the scheduler runs as the same user / $HOME that holds the ~/.claude login, and no ANTHROPIC_API_KEY / ANTHROPIC_AUTH_TOKEN / ANTHROPIC_BASE_URL is exported in the env that launches ahsir start (those would override the login and bill the API instead).

  • B. Anthropic API key: provider: anthropic + apiKey: ${ANTHROPIC_API_KEY}, model optional.
  • C. DeepSeek / Zhipu (Anthropic-compatible): provider: deepseek (or zhipu) + apiKey: ${MODEL_API_KEY} + model: deepseek-v4-pro; baseURL defaults per provider, so you can omit it.
  • D. Codex: command: codex + provider: codex, using an isolated per-agent CODEX_HOME and Codex's own login; baseURL is not supported here.

ahsir agent new scaffolds Anthropic defaults — recipe B (provider: anthropic, no baseURL → official api.anthropic.com, apiKey: ${ANTHROPIC_AUTH_TOKEN}, model: claude-opus-4-8). For recipe A (local login) pass --api-key-env ""; for C/D pass --provider deepseek|zhipu|codex. After editing a card, restart that agent (console「重启生效」or POST /admin/agents/{name}/restart) to apply.

Observability

  • ahsir trace [contextId] — the invocation ledger as an agent-call timeline: id, source (with speaker), agent, method, status, duration, preview.
  • ahsir history <agent> <contextId> — full transcript replay for one conversation.
  • ahsir doctor — health checklist: config file, provider CLIs on PATH, scheduler reachability, per-agent online status, and whether the CLI can find an admin token.
  • Structured logs. The scheduler tees agent stdout, so inter-agent A2A_CALL dispatches, turn timings, and token/cost stats are greppable in one place.

Authentication 2026-06-08

The control plane — agent lifecycle and registry write — is gated by a single admin token; the data plane (chat, history, tasks, trace, list) stays open in this baseline.

  • Auto-generated token. ahsir start writes a 0600 admin-token file beside ahsir.yaml on first run and reuses it after. AHSIR_ADMIN_TOKEN overrides the file (CI / containers) and touches no disk.
  • Zero-friction for the same user. The CLI reads the same file, so agent new/delete just work; a different OS user — unable to read the file — is locked out of the control plane.
  • Overwrite protection. An unauthenticated same-name registration is rejected (401), closing the silent registry-overwrite hole. Scheduler-spawned agents authenticate their heartbeat with the token via --admin-token.
  • Internal-token leak fix. The scheduler sends a per-agent internal token only to the loopback address it recorded at spawn time — never to a registry card URL, which a write could otherwise repoint at an attacker. Card-only agents receive no internal token.

  - name: backend
    workspace: /home/user/.ahsir/agents/backend  # private .a2a state (unique per agent)
    workdir: /home/user/projects/backend          # optional cwd; default = workspace. Share across agents.
    port: 0            # 0 = auto-allocate from port_range

registry:
  host: "127.0.0.1"    # loopback only
  port: 9800
  heartbeat_interval: 10s
  heartbeat_timeout: 30s

  chat: 10m            # gateway forward deadline; >= max agent runtime.timeout
  task_status: 30s

port_range:
  start: 9802
  end: 9900

Runtime state lives beside this file: .ahsir/ledger.jsonl (invocation ledger) and admin-token (0600). Both are git-ignored.

agent-card.yaml — one persona

name: teacher
description: A teacher agent that answers questions.
version: "1.0.0"
skills:
  - name: teaching
    description: Explain concepts and answer questions

  systemPrompt: |
    You are a helpful, knowledgeable teacher...

      command: npx

9 · Security model

The baseline establishes one real trust boundary and closes the highest-risk holes from the 2026-06-07 adversarial review. It is explicit about what it does not yet cover.

Two tokens, two purposes

TokenProtectsLifecycle
X-Ahsir-Admin-TokenControl plane: agent start/stop, registry write. Auto-generated 0600 file beside ahsir.yaml, or AHSIR_ADMIN_TOKEN. Shared by scheduler, CLI, and spawned agents.
X-Ahsir-Internal-TokenScheduler→agent A2A calls (per agent). Generated per spawn; sent only to the agent's recorded loopback address.

Trust boundary

The OS user who can read the admin-token file. On a shared machine, another user — blocked by 0600 — cannot start, stop, or hijack agents. The data plane (chat/read) is open at this level because the threat model is multi-user control-plane abuse, not eavesdropping on loopback.

Hardening already in place

  • Race-free registry and session pool; go test -race is the trusted gate.
  • Provider arg sanitizer strips sandbox/permission-bypass flags from runtime.args.
  • MaxBytesReader on all gateway bodies; ledger preview bounded to 512 bytes; ledger, agent-card, and transcript files written 0600.
  • Non-loopback network.bind rejected; A2A proxy settles the ledger only after the response body relays (interrupted streams record as failed).
